# План доработки Cook and Fry

> Сохранено: 2026-07-30.  
> Текущая задача: довести PWA-версию и админку до production-готовности.

## Что уже реализовано

- **Основной сайт** (`frontend/index.html`) — форма заказа, дизайн, выпадающий список компаний + ручной ввод.
- **PWA-версия** (`frontend/pwa.html`, `frontend/manifest.json`, `frontend/sw.js`, `frontend/icons/`) — мобильная форма заказа, адаптивная вёрстка, service worker, офлайн-баннер.
- **Админка** (`frontend/admin.html`) — вход по токену, таблица заказов, таблица «Заказчики» с CRUD, фильтры, статистика.
- **Бэкенд** (`src/routes/orders.js`, `src/routes/admin.js`) — API заказов, справочник компаний, CRUD заказчиков, миграции БД.
- **База данных** — таблицы `orders` и `customers` (см. `src/db/migrations.js`).
- **Тесты** — `npm test` и `npm run test:frontend` проходят.

## Оставшиеся шаги (по приоритету)

### 1. HTTPS + nginx (must have для PWA)
- PWA можно установить на телефон только с HTTPS.
- Поставить nginx перед Node.js, проксировать на `127.0.0.1:3001`.
- Получить сертификат Let’s Encrypt (например, через Certbot).
- Обновить `.env`: `BASE_URL=https://<домен>`.
- Проверить, что `manifest.json` и service worker отдаются корректно.

### 2. Сделать админку независимой от CDN
- Скачать `alpinejs@3.x.x` и `tailwindcss` локально в `frontend/vendor/`.
- Подключить в `frontend/admin.html` локальные файлы.
- Убрать зависимость от `cdn.tailwindcss.com` и `cdn.jsdelivr.net`.

### 3. Довести PWA до установки
- Проверить установку на Android (Chrome) и iOS (Safari → «На экран Домой»).
- Добавить в `pwa.html` подсказку/кнопку «Установить приложение» (beforeinstallprompt).
- Проверить, что иконки и тема корректно отображаются.

### 4. Офлайн-очередь заказов в PWA (опционально, но желательно)
- При отсутствии сети сохранять заказ в `IndexedDB`.
- При восстановлении соединения автоматически отправлять накопленные заказы.
- Показывать пользователю статус: «Заказ сохранён, будет отправлен при появлении интернета».

### 5. Настроить уведомления администратора
- Заполнить в `.env`: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`, `VK_BOT_TOKEN`, `VK_PEER_ID`, `MAX_BOT_TOKEN`, `MAX_CHAT_ID`.
- Проверить, что `src/notifications/index.js` отправляет сообщение при новом заказе.

### 6. Автоматический бэкап БД
- Добавить cron-задачу (или скрипт в `scripts/backup.sh`) для ежедневного копирования `data/orders.db`.
- Хранить копии локально в `backups/` и, по возможности, выгружать на внешнее хранилище.

### 7. Финальное приёмочное тестирование
- Создать 2 компании в админке («Заказчики»).
- Оформить заказ через основной сайт.
- Оформить заказ через PWA.
- Проверить, что оба заказа видны в админке, фильтры по компаниям работают.
- Проверить смену статуса заказа и обновление статистики.

## Технические заметки

- Порт приложения: `3001` (задаётся в `.env` или `ecosystem.config.js`).
- Админ-токен передаётся в заголовке `X-Admin-Token`.
- API компаний: `GET /api/orders/companies` (публичный) и `GET /api/admin/companies`.
- API заказчиков: `GET/POST/PATCH/DELETE /api/admin/customers`.
- Service worker кэширует только статику (`/pwa.html`, `/manifest.json`, иконки). API-запросы не кэширует.
- PWA не использует внешние CDN — только inline-стили и vanilla JS.
